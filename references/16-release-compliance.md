# 16. 对外发布前的资料、事实与合规控制

> 本文件是研究工作流，不是法律意见或机构合规批准。正式对外发布需遵守所属机构适用的监管规范、内部审批、信息隔离及披露政策。

## 四类审核边界

### 一、事实与模型（研究员负责）

核心观点有依据；原始链接可访问，文件、页码、原表和数据口径准确；重要数字交叉验证；预测公式、三表勾稽及敏感性重算通过；修改文字后再做一次数字与来源核对。

### 二、来源许可（制作人负责）

核查数据库、图表、图片、新闻与第三方报告的转载、改编和公开发行许可。公开资料可访问不等于有版权再发行权；不能复制其他机构研究报告的图、段落或特色编排。图表尽可能自行依据合规数据重绘，保留原始出处、许可证或授权记录。

### 三、敏感信息与利益冲突（授权人员复核）

不得把未公开重大信息、客户保密记录、闭门会议未经允许披露的内容或个人隐私当作公开研究材料。确认研究报告的作者、机构身份、利益冲突披露、评级定义、覆盖范围、发布日期和所需声明。

### 四、机构发布流程（必须人工）

必要时完成研究负责人复核、数据核查、合规审批、法务或交易限制核验、发行前留痕及版本锁定。自动脚本、AI 输出、质量分数都不能代替签核。

## 发布状态分级

- `RESEARCH_DRAFT`：研究中的工作稿，可以存在未核实假设，但必须标出。
- `FACT_CHECK`：研究员已提交来源台账和模型，等待事实核对。
- `COMPLIANCE_REVIEW`：事实核查已通过，等待机构审批和披露补足。
- `APPROVED_FOR_RELEASE`：授权人员确认满足机构要求，方可进入外发动作；Skill 不自行授予该状态。
- `BLOCKED`：资料来源、模型、版权、敏感信息或利益冲突存在阻断项。

## 一票否决

- 核心数据或结论无可追溯依据，重大口径冲突无法解释。
- 未公开重大信息、保密数据或未授权版权内容将进入公开稿。
- 预测标成历史事实，产能与销量混用，财务模型核心数不勾稽。
- 必要利益冲突、风险、评级说明、审批或版本记录缺失。
- 通过 AI/脚本或个人身份绕过机构发稿审批。

## 报告发布包

保留：最终稿、原始资料路径与检索日期、证据台账、模型及锁定版本、图表数据和许可、审批签核、审稿意见及处理、发布主体/日期/版本。敏感底稿只存获准的内部系统，不应提交 GitHub 仓库。
